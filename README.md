# Proxy Bot — Telegram-бот на API реселлера Steel Proxy

Бот-магазин прокси: покупатель пополняет внутренний баланс, выбирает тип → локацию → срок → количество
и сразу получает прокси. Заказы создаются через [API реселлера Steel Proxy](https://api.steelproxy.com/docs),
номера заказов совпадают с основной системой Steel Proxy.

## Что умеет

**Покупатель**
- каталог из API: типы прокси, локации с флагами, сроки (включая 2/3/6 месяцев, если у локации есть тариф на 30 дней);
- цены = ваша закупочная цена × наценка (`MARKUP_PERCENT`), округление вверх до рубля;
- мгновенная выдача: логин/пароль, строки HTTP, HTTPS (тот же порт, что и HTTP) и SOCKS5; больше 10 прокси — файлом `.txt`;
- «Мои заказы»: актуальные данные из API, скачать списком, продлить на 1/2/3/6 месяцев;
- напоминание за сутки до окончания заказа с кнопкой «Продлить»;
- пополнение баланса: криптовалютой через xRocket Pay с автоматическим зачислением, или переводом по реквизитам с чеком, который админ подтверждает кнопкой.

**Администратор** (`/admin` — список команд)
- уведомления о каждой продаже с прибылью и остатком баланса Steel Proxy, предупреждение о низком балансе;
- кнопки «Зачислить / Отклонить» для заявок на пополнение;
- `/stats`, `/user`, `/give`, `/take`, `/ban`, `/unban`, `/sporders`, `/reload`, `/broadcast`, `/check`.

## Деньги и надёжность

- Балансы хранятся в копейках (SQLite, `data/shop.db`).
- Порядок покупки: списываем с покупателя → создаём заказ в API. Если API вернул ошибку
  (402/404/409/502…) — деньги сразу возвращаются, покупателю показывается текст из документации.
- Если связь оборвалась уже после отправки запроса, бот ищет заказ по `buyer_reference`
  (`tg<user>-o<id>`) в списке заказов Steel Proxy. Нашёл — выдаёт прокси, нет — заказ помечается
  «проверяется», админ получает уведомление и командой `/check <id>` выдаёт или возвращает деньги.
- Повторное нажатие «Оплатить» не создаёт второй заказ (блокировка на пользователя).

## Установка на VPS

Боту не нужны входящие порты, домен и nginx: он работает через long polling. Установка
не трогает файрвол, nginx и другие сайты на сервере.

**1. Положите код на сервер.** Скачайте архив (GitHub → Code → Download ZIP), загрузите его
на сервер и распакуйте:

```bash
sudo mkdir -p /opt/proxy-bot && cd /opt/proxy-bot
sudo unzip ~/proxy-bot-main.zip            # распакуется в папку proxy-bot-main
shopt -s dotglob && sudo mv proxy-bot-main/* . && sudo rmdir proxy-bot-main
sudo chmod +x deploy/*.sh
```

**2. Запустите установку:**

```bash
sudo bash deploy/setup.sh
```

Скрипт спросит токен бота, API-ключ Steel Proxy и ваш Telegram ID, проверит ключ в API,
соберёт и запустит контейнер, убедится, что бот поднялся, и включит ежедневный бэкап базы
в 03:40 (`backups/`, последние 14 копий). Наценку, реквизиты для пополнения, контакт поддержки
и название магазина поменяйте в `/opt/proxy-bot/.env`, затем `docker compose up -d`.

## Оплата криптовалютой (xRocket Pay)

Устроено как в Тайнике. Покупатель выбирает сумму в рублях и валюту (USDT, TON, TRX…), бот
выставляет счёт в [xRocket Pay](https://docs.xrocket.exchange/api/pay/pay-api-overview) по
текущему курсу, покупатель платит в @xRocket, и рубли сами зачисляются на баланс в боте.
Деньги приходят на баланс вашего приложения в @xRocket (за вычетом комиссии xRocket), вывод там же.

**Включить:**

1. В Telegram: [@xRocket](https://t.me/xRocket) → **Pay API** → **Создать приложение**. В настройках
   приложения: **API Version → Current**, затем **🔑 API Token**.
2. Допишите в `.env`:
   ```
   XROCKET_PAY_TOKEN=api-токен
   XROCKET_CURRENCIES=USDT,TONCOIN,TRX
   ```
3. `docker compose up -d`. В журнале появится «Оплата через xRocket Pay включена».

Проверить без настоящих денег: токен из [@xrocket_testnet_bot](https://t.me/xrocket_testnet_bot)
и `XROCKET_TESTNET=1`.

**Как бот узнаёт об оплате.** По умолчанию он проверяет неоплаченные счета каждые 30 секунд, плюс
у покупателя есть кнопка «Проверить оплату». Домен и nginx для этого не нужны.

**Мгновенно, через вебхук (необязательно).** Нужен домен с HTTPS на этом сервере.
1. В приложении xRocket выпустите **🔑 Webhook Token**.
2. В `.env`:
   ```
   XROCKET_WEBHOOK_URL=https://pay.ваш-домен/xrocket
   XROCKET_WEBHOOK_SECRET=webhook-токен
   ```
3. Откройте порт контейнера только для nginx: создайте рядом с `docker-compose.yml` файл
   `docker-compose.override.yml` (обновления его не трогают):
   ```yaml
   services:
     proxy-bot:
       ports:
         - "127.0.0.1:8090:8090"
   ```
4. В nginx для домена: `location /xrocket { proxy_pass http://127.0.0.1:8090; }`, затем
   `nginx -t && systemctl reload nginx` и `docker compose up -d`.

Адрес вебхука бот сам передаёт в каждом счёте. Принимаются только уведомления с верной подписью
HMAC-SHA256, не старше 5 минут; сумма и валюта сверяются со счётом; один счёт зачисляется
ровно один раз. Сверка раз в 30 секунд продолжает работать и с вебхуком, на случай если
уведомление потерялось.

**Детали:**
- Сумма в крипте считается по курсу xRocket к рублю и округляется вверх. Если xRocket не отдаёт
  курс к рублю, задайте `RUB_PER_USD`: тогда бот возьмёт курс к доллару и пересчитает.
- Счёт действует час. Повторный запрос той же суммы в той же валюте возвращает уже выставленный счёт.
- В xRocket уходят только сумма, валюта, описание «Пополнение баланса на N ₽» и случайный номер
  счёта. Telegram ID, имя и @username покупателя не передаются. То же написано в Политике
  конфиденциальности.
- Ручное пополнение по реквизитам с чеком остаётся вторым способом, если задан `PAYMENT_INFO`.
  С xRocket и пустым `PAYMENT_INFO` этот способ скрыт.
- `/stats` показывает число и сумму пополнений через xRocket.

## Документы, цены и поддержка (для банка)

Для согласования эквайринга в боте есть всё, что обычно просит банк:

| Что | Где в боте |
| --- | --- |
| Пользовательское соглашение | /terms, кнопка «📄 Документы» |
| Политика конфиденциальности | /privacy, кнопка «📄 Документы» |
| Цены и тарифы (живая таблица из каталога с наценкой) | /prices, кнопка «💲 Цены» |
| Контакты поддержки и обращения | /support, кнопка «🆘 Поддержка» → «Написать в поддержку» |

Ссылки на документы есть в приветствии, а при пополнении баланса бот предупреждает, что оплата
означает согласие с Соглашением.

**Что заполнить в `.env`** (затем `docker compose up -d`):

```
OPERATOR_NAME=ИП Иванов Иван Иванович     # как в договоре с банком
OPERATOR_INN=660000000000
SUPPORT_CONTACT=@ваш_username             # человек, не группа
SUPPORT_EMAIL=support@ваш-домен
```

**Ссылки для банка:** напишите боту `/publish` (от админа). Он опубликует соглашение, политику
и цены на telegra.ph и пришлёт три постоянные ссылки. Страница цен потом обновляется сама раз
в 6 часов. После правки `.env` запустите `/publish` ещё раз, ссылки не изменятся.

**Обращения в поддержку.** Пользователь пишет в боте, а вам приходит «🆘 Обращение #N» и копия
сообщения. Ответьте на неё реплаем, и ответ уйдёт пользователю с кнопкой «Ответить». Открытые
обращения — `/tickets`. Удалить данные пользователя по его запросу — `/deluser <id>`
(так обещает Политика конфиденциальности, п. 6.2).

Тексты лежат в `bot/docs.py`; при правке поменяйте `DOCS_REVISION` (или `DOCS_DATE` в `.env`).

## Работа через прокси

Если на сервере заблокирован Telegram (или он работает с перебоями), пропишите прокси в `.env`
и перезапустите бота:

```bash
cd /opt/proxy-bot
nano .env        # TELEGRAM_PROXY=socks5://login:pass@host:port
docker compose up -d
docker compose logs --tail 20 proxy-bot   # должно быть «Telegram — через прокси …» и «Бот запущен»
```

- Поддерживаются `socks5://` и `http://`, с логином и паролем или без.
- Подойдёт любой ваш прокси, в том числе купленный у Steel Proxy: из строки
  `login:pass@host:3072` получится `socks5://login:pass@host:3072`, из `…:3071` —
  `http://login:pass@host:3071`. Локация прокси должна быть там, где Telegram не блокируется.
- Прокси, запущенный на самом сервере вне Docker, указывайте через `host.docker.internal`,
  а не `127.0.0.1`: внутри контейнера `127.0.0.1` — это сам контейнер. Сам прокси при этом
  должен слушать не только `127.0.0.1` (например, `0.0.0.0` или адрес моста `172.17.0.1`).
- Через прокси идут только запросы к Telegram. Запросы к API Steel Proxy идут напрямую;
  если нужно и их пустить через прокси — задайте `STEELPROXY_PROXY` в том же формате.
- Пароль прокси в журнал не пишется: там видно `socks5://login:***@host:port`.

## Обновление кнопкой из GitHub

Устроено так же, как в Тайнике.

**Один раз на сервере:**

```bash
cd /opt/proxy-bot
sudo ./deploy/connect-github.sh nshimanovskiy/proxy-bot
```

1. Скрипт создаст ключ **только для чтения** и попросит добавить его в
   **Settings → Deploy keys** репозитория (галочку «Allow write access» не ставить).
2. Подключит папку к репозиторию. `.env`, `data/` (база) и `backups/` останутся на месте.
3. Создаст пользователя `proxy-bot-deploy` и ключ для GitHub Actions. Этот ключ может только
   запустить `deploy/remote-deploy.sh` (forced command + одно правило sudo): ни консоли,
   ни других команд. Вход root по SSH не нужен.
4. Напечатает значения для **Settings → Secrets and variables → Actions**:
   `DEPLOY_HOST`, `DEPLOY_PORT`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS`, `DEPLOY_KEY`.

**Дальше:** GitHub → **Actions → «Деплой бота» → Run workflow**. Workflow прогоняет тесты,
заходит на сервер, делает бэкап базы, забирает `main`, пересобирает контейнер и проверяет,
что бот запустился. Если бот не поднялся — запуск в Actions краснеет, а в логе видны
последние строки журнала бота.

## Повседневное

| Задача | Команда (в `/opt/proxy-bot`) |
|---|---|
| Состояние | `docker compose ps` |
| Журнал | `docker compose logs -f proxy-bot` |
| Обновить вручную | `sudo ./deploy/update.sh` |
| Проверить запуск | `./deploy/check.sh` |
| Бэкап вручную | `sudo ./deploy/backup.sh` → `backups/proxy-bot-ДАТА.db.gz` |
| Перезапуск | `docker compose restart proxy-bot` |

### Восстановление из бэкапа

```bash
docker compose stop proxy-bot
gunzip -c backups/proxy-bot-ДАТА.db.gz > data/shop.db
rm -f data/shop.db-wal data/shop.db-shm
docker compose start proxy-bot
```

## Тесты

```bash
pip install -r requirements.txt
python -m unittest -v
```

`tests/test_proxy.py` — запросы в Telegram и Steel Proxy через SOCKS5 и HTTP-прокси с паролем
(поднимает локальный мини-прокси и проверяет, что трафик идёт через него).
`tests/test_shop.py` — деньги: наценка, списания, возвраты при ошибках API, сверка после обрыва
связи, продление. `tests/test_bot.py` — сквозной сценарий через настоящий диспетчер aiogram
с подменённым Telegram и API. Тесты запускаются при каждом push и перед каждым деплоем.

## Локальный запуск без Docker

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env && nano .env
python -m bot.main
```

